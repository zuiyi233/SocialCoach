# 恋爱互动叙事与陪伴层（spec）

> 状态：**方案，未开工**（2026-10-20）
> 范围：只动恋爱域（`/love`、`/love/play/*`、`components/love/*`、`lib/love-*`）；不碰 `/practice`、`/api/assess`、能力雷达、教练复盘与情商统计。
> 关联：[视觉小说模式](./spec-love-visual-novel.md) · [GALGAME 基本盘](./spec-love-galgame-foundation.md) · [Rio 六幕](./spec-love-rio-route.md) · [参考研究](../refs/galgame-companion-research.md)
> **2026-10-21 方向修订**：本文「不做好感数值」的条目由 [spec-love-semi-coach.md](./spec-love-semi-coach.md) 的关系状态取代；阅读层、记忆、Rio 路线与结局继续有效。恋爱域现在分半教练与 Love Studio 两套系统，见 [14-stage-f.md](../14-stage-f.md)。跨系统的局外成长（叙事阶段 + 关系图鉴 + 故事收藏，无 EXP/等级）见 [spec-love-bridge.md](./spec-love-bridge.md) §6。

## 一、目标

把恋爱模块从「单场 AI 对话 + 一条 4 幕 Rio」升级为**可读完的互动小说 + 会记得你的陪伴层**。

一句话验收：**玩家能像玩 GALGAME 一样连续读、选、回看、读档、看到结局；关掉再回来，角色会在故事里提起上次的选择或承诺，而不是重新开始。**

三条产品支柱：

1. **后果可见**：选择改变后续台词、可选行动、条件与结局，而不是只改一句即时回复。
2. **阅读舒适**：auto、skip-read、backlog、多槽存读档、章节选择、结局图鉴、字号/速度、BGM/SFX。
3. **陪伴连续**：设备端记忆、时间感知的回归开场、承诺回访、角色自己的目标与边界；**不做**签到、惩罚性 streak；好感改为非可刷的关系状态（2026-10-21 修订，见 [spec-love-semi-coach.md](./spec-love-semi-coach.md)）。

## 二、研究结论（详见 [参考研究](../refs/galgame-companion-research.md)）

- **选择重量 ≠ 分支数量。** 428 / Late Shift 的分支极多，玩家记住的是后续被点名的旧选择；没有 callback 的分支只是读档试错。我们应优先把 Rio 的 flags / promise / boundary 变成第 5–6 幕的开场变体、台词引用与失败补救。
- **阅读层是 GALGAME 的底线。** backlog、auto、skip-read、多槽存读档、文本设置、章节选择、结局图鉴；CG/BGM 是加成，不是骨架。当前我们只有 backlog + 单句重播。
- **AI 生成破坏传统 skip-read。** 重开时模型生成不同句子，按“行 id 已读”跳过没有意义；只能跳过**逐字相同**的已见文本或作者拍点。方案必须把这条限制写进产品说明。
- **陪伴感可工程化为记忆、时间、承诺、角色目标。** 网页没有可靠后台，「主动」只能做成**下次打开时补演**；真推送需要服务端，违反无账号约束。
- **AIcove 借机制不借运行时。** 借两层记忆、来源可追、用户可锁可删、打扰预算、角色卡/世界书；不借 Android 后台服务、云账号、原生实时通话。

## 四、产品方案

### 4.1 三层结构

```
┌──────────────────────────────────────────────┐
│ 陪伴层（跨会话）                              │
│  记忆档案 · 回归开场 · 承诺回访 · 时间感知     │
├──────────────────────────────────────────────┤
│ 故事层（一次游玩）                            │
│  章节/幕 · 作者拍点 · 账本 · 条件 · 结局       │
├──────────────────────────────────────────────┤
│ 阅读层（呈现与操作）                          │
│  舞台 · 台词 · auto/skip · 存档 · 回想 · 图鉴  │
└──────────────────────────────────────────────┘
```

**故事层**决定“发生什么”，**阅读层**决定“读起来像不像 GALGAME”，**陪伴层**决定“关掉之后还像不像有人在那里”。三层共用 `LoveStoryStore` 与 `socialcoach.love-play.*` 前缀，不引入第二套账号或服务端。

### 4.2 故事层：作者拍点 + 模型连接词

保留现有契约（详见 Rio spec）：

- **作者写死的关键拍点**：开场变体、状态选项、结局条件、必须出现/禁止出现的台词。它们是评测与状态写入的唯一证据。
- **模型生成连接词**：普通回合的台词与选项；允许模型发挥，但不能改写拍点、不能提前泄露 `hidden`、不能替 NPC 让步。
- **每一幕声明四件事**：`reads`（读哪些账本字段）、`writes`（只写本幕允许的字段）、`callbacks`（下一幕必须被点名的旧选择/承诺）、`endings`（本幕可判定的结局）。
- **后果可见清单**：至少三类可见后果——开场变体、台词引用（NPC 说“你上次说……”）、可选行动变化（某选项只在/不再出现）。每幕验收必须逐条列出。

**章节与路线**：

- 一条线 = 一个 `series`，按 `series.order` 排序；每一幕有 `act` 编号与稳定 `sceneId`。
- 路线锁：前一幕未完成不默认解锁下一幕；已完成的幕可从系列页回看（见 4.3 章节选择）。
- 结局：命名结局由事实谓词决定（Rio 已有 `resolveRioEnding`）；普通场景仍用 success/partial/failure，不新增好感分。
- 内容策略：Rio 5–6 完成主线；之后再开 1 条同人连续线。**不追求 87 个结局**，先做到“每个主要选择都能在第 5–6 幕被点到”。

### 4.3 阅读层：把“网页”变成“视觉小说”

优先级从高到低：

1. **G24：所有恋爱场景进 GALGAME 入口。** 当前 `/love` 只有 21 场走 `/love/play`，43 场点击后仍创建教练 Session。改为：场景卡片主入口进 `/love/play/<id>`，教练练习保留为次入口。无 series 的场景直接复用 `PlayScene`，完成仍写 `LovePlayRecord`，不写 series progress。
2. **Auto**：一句台词打完字、TTS 播完后自动进入下一句；任何点击/按键/选项/打开面板立即取消。速度可调；TTS 关闭时按文本速度计时。
3. **Skip-read**：只跳**逐字已见**的文本或作者拍点。稳定键用 `scenarioId + 文本哈希`（或作者拍点 id），不能用每局随机的 `line.id`。动态生成的新句子不跳；界面明确写“只跳过读过的内容”。
4. **多槽存档**：每场 1 个自动档 + 3 个手动槽；存档必须同时保存 `history`、`options`、`routeState`、series progress 快照、`recorded`、read 集合。读档后 revision 重新同步；导出/擦除覆盖所有槽。
5. **章节选择**：从系列页进入任一幕时，恢复该幕开始时的账本快照（不是最新账本），避免第 5 幕读档后第 4 幕的 flag 倒退。首版可只允许“从已完成幕的开头重玩”，并在进入前提示会覆盖该幕之后的进度。
6. **结局图鉴 / 路线图**：从 `LovePlayRecord` + 作者结局表派生；只展示已遇到的结局与已走过的幕，不剧透未遇到的分支。
7. **文本设置**：字号、行距、打字速度、auto 速度、减少动效；持久化在 settings。
8. **BGM/SFX（P3）**：按场景 tone 选曲；TTS 播放时自动 ducking；授权与来源写入 manifest。

**不做**：rollback（LLM 回滚会重写历史）、全语音包、任意跳章、运行时出图。

### 4.4 陪伴层：记忆、时间、承诺、目标

#### 记忆档案（设备端）

- 每条记忆：`id`、`kind`（fact / preference / promise / boundary / event）、`text`、`sourceMessageIds`、`seriesId`、`characterKey`、`createdAt`、`updatedAt`、`locked`。
- **原文是唯一真相**：记忆只能从已确认的 `history` 抽取；删除原文时对应记忆标记失效，不保留无源记忆。
- 两层：`core`（每幕都带的 3–5 条：当前关系状态、未兑现承诺、最重要偏好/边界）+ `archive`（按关键词/标签检索，最多 6 条）。不把整段历史塞进 prompt。
- **抽取时机**：一幕结束或用户点“整理这段记忆”时；不做每条消息后台抽取，不增加后台模型调用。抽取失败不影响剧情。
- 用户可查看、编辑、删除、锁定；锁定条目不会被后续整理覆盖。
- 作用域：`seriesId + characterKey`；**绝不跨线/跨 NPC**。换人的线不声称“记得”。

#### 时间感知与回归开场

- 记录 `lastVisitAt`、`lastSceneId`、`lastChoiceSummary`、`openPromises`；打开 `/love` 或下一幕时计算离开时长。
- 回归开场用**作者写死的模板**（零模型调用）：例如“上次你说会在这周六前给她答复——现在还想说吗？”；模板槽位只能填已确认的承诺/原话，不编造。
- 不做“你不回我就生气”的惩罚、不做 streak、不做虚假的实时在线。离开很久只影响一句开场，不影响数值。

#### 承诺与回访

- 复用 `love-carry-store` 的承诺对象与跟进卡；把 `dueByAct` 扩到第 5–6 幕，到期必须被点名。
- 承诺未兑现时，NPC 可以失望、追问、设边界，但不扣分、不 game over；给修复路径。
- 回访节奏沿用现有节流：日上限、间隔、免打扰；**站内 only**；不承诺 push。

#### 角色目标与边界

- 每幕角色卡增加 `goal`、`redLine`、`secret`（作者写死，双语，带 source）。模型提示里作为“不可让步”的约束；验收检查 NPC 不因玩家态度好而放弃目标。
- 关系状态仍只记承诺、边界、冲突、仪式、flags、最终决定与逐字证据；**2026-10-21 修订**：允许熟悉 / 信任 / 心动三维关系状态，但不做可刷的好感 / 亲密度数值（见 [spec-love-semi-coach.md](./spec-love-semi-coach.md)）。

### 4.5 呈现层：章节卡与镜头感

- 章节卡：幕号、标题、时间/地点、一句引子；黑场 + 渐入；可跳过。
- 舞台：现有立绘 + CSS 背景；增加“近景/中景/远景”三档缩放与左右站位，用 Framer Motion 转场；不新增运行时渲染。
- 关键拍点：重点台词可触发轻震/闪白/静音一拍；遵守 `prefers-reduced-motion`。
- 限时选择（可选）：只用于高潮，倒计时在台词与 TTS 完成后开始；设置里可关闭；超时按“沉默”分支处理，不直接失败。
- BGM/SFX：构建期资产 + manifest（来源/授权/场景），无素材时静默降级。

### 4.6 数据与架构

**新增/扩展（全部在 love 前缀下）：**

| 数据 | 键/位置 | 说明 |
|---|---|---|
| 手动槽 | `LoveStoryStore.slots`（v2） | `Record<sceneId, Record<slot, LovePlaySave>>`；与自动档同 schema；导出/擦除覆盖 |
| 已读 | `LoveStoryStore.read` 或 `socialcoach.love-play.read` | `Record<contentKey, true>`；contentKey = `sceneId:sha1(text)` 或作者拍点 id；上限与清理策略 |
| 记忆 | `socialcoach.love-play.memory` | 单 slot、按 `seriesId:characterKey` 分组；schema 校验；导出/擦除 |
| 回归 | `socialcoach.love-play.visit` | `lastVisitAt`、`lastSceneId`、`openPromiseIds`；小对象 |
| 结局图鉴 | 派生 | 从 `records` + `data/love-endings.ts` 派生，不新增存储 |
| 章首账本 | `routes[seriesId].byAct`（v2） | 每幕开始时的 `{rio, appliedBeats}` 快照；用于章节选择 |

**迁移**：`LoveStoryStore` v1 → v2；v1 的 `saves` 作为自动档，`slots/read/byAct` 为空；读失败保留 raw，不自动覆盖（沿用现有恢复 sheet）。

**隔离**：

- 新代码只在 `app/src/lib/love-*`、`app/src/components/love/*`、`app/src/app/love/*`；不 import `lib/tasks/practice`、`/api/assess`、`proficiency`。
- 所有存储键在 `socialcoach.love-play.*`；`buildBackupPayload()` / `clearLovePlaySlots()` / 设置页重置必须覆盖新键；测试断言 round-trip 与擦除。
- 陪伴记忆只注入 `/api/love-play` 的 prompt；不进教练、3D、复盘、调度。
- 复用现有 `speak` / `playNpcLine` / `LOVE_VOICES`，不新建第二套语音栈。

> 估算按“纯前端 + 现有 LLM + 设备端存储”计；不含内容写作与美术资产的生产时间。

- [ ] 承诺 `dueByAct` 扩到 5–6 幕；到期点名与修复路径

**验收**：每条记忆有 `sourceMessageIds`；删除原文后记忆失效；回归开场只引用已确认事实；承诺到期在下一幕被点名；不写任何 EQ 数值。

**估算**：6–8 人日。

### P2：Rio 5–6 与命名结局（内容收口）

- [ ] 第 5 幕：家庭期待/决定归属；第 6 幕：期限之夜 + `said-it-plain` / `clean-parting`
- [ ] 前 4 幕的 flags/promise/boundary 在第 5–6 幕产生可见 callback
- [ ] live 探针覆盖六类回应；hidden 不提前泄露；失败可修复
- [ ] 明确记录：**人工试玩闸门被产品决定豁免，内容未经玩家验证**

**验收**：E1/E2 都可在游戏内到达；同一条线两条结局都能从已有关键选择解释；不写分；无剧透。

- [ ] 章节卡、景别/站位、关键拍点动效、限时选择（可关闭）

**估算**：8–12 人日 + 资产。

## 六、验收总口径（不依赖真机/真人）

- **自动化**：`pnpm check`、`build`、`check-corpus`、`check-landing-ssr`、core/dinner 全绿；新增纯函数测试覆盖 read key、槽位迁移、记忆来源、章首快照、结局图鉴。
- **浏览器**：用 `browser-use` 连真实 Chromium（详见已记录的验收路径）；种固定存档验证续玩、auto、skip、存读档、图鉴、坏档恢复。
- **Live 探针**：每条新幕按六类回应（标准/施压/拒绝/反问/玩笑/修复）跑；hidden 只对合法问题出现；不让步、不出戏；429 退避。
- **静态**：新语料带 source；新文案 `L(zh,en)`；剧透探针零泄漏；love 键全部可导出/擦除；EQ 测试与页面零改动。
- **不声称**：玩家是否“感觉到陪伴”无法在无真人试玩下证明；最多用“回归开场引用了已确认承诺/原话”作为代理指标，并在验收记录里注明。

## 七、非目标

- 不做 iOS/Android 客户端、真机推送、云存档、账号体系、服务端存储或服务端密钥。
- 不做真人 FMV、全动态捕捉、多人投票、实时直播互动。
- 不做可刷的好感 / 亲密度 / 签到 / streak；关系状态只在对的故事节点变化（2026-10-21 修订，见 [spec-love-semi-coach.md](./spec-love-semi-coach.md)）。
- 不做运行时图像生成、全量语音包、任意跳章、rollback。

- 不把恋爱记录回流到 `/practice`、`assess`、能力雷达、首页教练回访。

## 九、风险

- **AI 生成 + 已读**：动态文本无法全局 skip；若玩家期待“全跳过”，会失望。产品文案要提前说明。
- **章节选择回滚**：账本/承诺/已读必须一起回滚，否则会出现“第 5 幕知道第 6 幕的事”。首版限制从已完成幕重玩，降低复杂度。
- **记忆成本与矛盾**：模型抽取会花钱、会写错；必须来源可追、用户可删、锁定优先，宁可少记。
- **陪伴变打扰**：站内回访也要有预算；不用愧疚文案，不做“你不回就掉好感”。
- **内容量**：一条 6 幕线 + 多结局的写作成本远高于代码；先 Rio，再决定第二条线。
- **无真人验证**：所有“陪伴感/剧情打动”结论都只能标为未验证，不能用自动化冒充。

## 十、执行顺序（建议）

1. **P0 入口 + 阅读层**：先让 64 场都能像 GALGAME 一样被读到；这是最高性价比。
2. **P1 陪伴层**：记忆、回归、承诺；这是与普通视觉小说的差异点。
3. **P2 Rio 5–6**：在壳与陪伴层稳定后收主线；豁免人工闸门要单独记录。
4. **P3 电影感**：有素材再做，不阻塞前两步。
