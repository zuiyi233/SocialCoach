# 恋爱半教练系统（spec）

> 状态：**方案，未开工**（2026-10-21 立项）
> 范围：恋爱系统的定位、内容契约、好感/关系状态、主动关心、可选反馈。剧本引擎与阅读层继续沿用 [spec-love-interactive-story.md](./spec-love-interactive-story.md) 的成果；不碰主教练。
> 关联：[Love Studio](./spec-love-studio.md) · [剧本模式美术升级](./spec-love-scripted-art.md) · [GALGAME 基本盘](./spec-love-galgame-foundation.md) · [视觉小说模式](./spec-love-visual-novel.md)

## 0. 结论一句话

恋爱系统不是「加了立绘的教练」，也不是「纯 Galgame」。它是**半教练**：用关系状态（熟悉 / 信任 / 心动）驱动角色主动关心，用可选、基于用户自由输入的回顾告诉用户怎么爱得更好；不强制每次让步或拒绝，不写能力分，不用好感度惩罚缺席。

## 1. 两套系统与用户旅程

| 系统 | 一句话 | 主要入口 | 承担什么 |
|---|---|---|---|
| **恋爱系统（半教练）** | 有关系状态、会主动关心的恋爱练习 | `/love` 的剧本模式 | 告诉用户怎么更好地恋爱；可选回顾；内置 66 场 + 自定义场景 |
| **Galgame 系统（Love Studio）** | 用户生成文本、人物、立绘、场景的恋爱沙盒 | `/love` 的「先玩一局」 | 初始实践、沉浸、UGC；不做教学评分 |
| **主教练** | 阻力、证据式复盘的社交训练 | `/practice`、`/3d`、自定义排练 | 不因恋爱方向改变 |

**用户旅程**：`/love` → 「先玩一局」进入 Love Studio → 玩完得到关系回顾 / 角色与故事包 → 「把这段关系带回半教练」→ 进入带关系状态的剧本模式。用户也可以跳过 Studio，直接进入半教练。

**两套系统共享**：persona / 称呼 / 语言、恋爱情境分类、角色包与故事包。**不共享**服务端存储（v1 都是设备端或本地 Studio）。

## 2. 三套内容契约

这是本次方向修订的核心。主教练的领域规则不再拿来否决恋爱与 Galgame 需求；平台级约束（授权、安全、导出/擦除、产品名）仍然适用。

| 维度 | 主教练 | 恋爱半教练 | Galgame（Love Studio） |
|---|---|---|---|
| NPC 姿态 | 不讨好、阻力、不提前吐 `hidden` | 可以亲近、主动、关心；角色有自己的生活与边界，但边界是戏剧需要，不是教学阻力 | 恋爱体验优先；可以讨好、可以主动 |
| 反馈 | 强制证据式复盘，必须引用原话 | 可选「关系回顾」；引用用户**自由输入**的原话；不评分 | 不做教学反馈 |
| 数值 | 能力估计、熟练度 | 关系状态（熟悉/信任/心动，非可刷分数）+ 可选的恋爱技能视图 | 剧情 flag / 演出状态；不做技能分 |
| 剧情 | 目标、成功/失败、让步/拒绝验收 | 关系节点、结局、主动关心；不要求每场都有拒绝 | 自由生成 / 卡 / 世界书 |
| 内容来源 | 内置语料，必须有 `source` | 内置语料 + 自定义场景 | UGC：Tavern 卡、世界书、生成内容 |
| 存储 | 设备端 | 设备端 | v1 本地 Studio（SQLite）；托管版另议 |
| 运行时 | Next.js | Next.js | AnimaVN fork（Python + SQLite），独立服务 |

## 3. 好感 / 关系状态

### 3.1 不做可刷分数

- 不做签到、streak、每日任务、付费加成；不做「说对一句 +10 好感」。
- 好感不是一个要最大化的单一数值；它是**三个维度的关系状态**，只在有意义的故事节点变化。
- 不因为用户几天没来就扣关系；缺席不是惩罚项。

### 3.2 三个维度

| 维度 | 含义 | 主要信号 |
|---|---|---|
| **熟悉** | 共同经历与相处时间 | 完成同一角色/线的场景、回访、共同记忆 |
| **信任** | 对方是否觉得你可预期、可依靠 | 承诺兑现、边界被尊重、自由输入里的诚实表达 |
| **心动** | 恋爱张力与相互回应 | 关键场景的选择、自由输入、角色自己的节奏 |

存储形状（放进现有 story slot，不新开一套导出路径）：

```ts
type LoveRelationshipTier = 0 | 1 | 2 | 3; // 陌生 / 认识 / 熟络 / 亲近

interface LoveRelationshipState {
  v: 1;
  /** seriesId:characterId 或 scenarioId:characterId；同一角色跨幕连续，撞名按快照名处理 */
  characterKey: string;
  familiarity: LoveRelationshipTier;
  trust: LoveRelationshipTier;
  attraction: LoveRelationshipTier;
  /** 只留最近 20 条；每条有 kind / at / 可选逐字 quote */
  signals: {
    kind: "promise-kept" | "promise-broken" | "boundary-respected" | "free-text" | "return" | "scene-end";
    at: number;
    quote?: string;
  }[];
  updatedAt: number;
}
```

- 列表页用**定性描述**（「她最近会先问你今天怎么样」），不展示可刷的百分比；调试/无障碍场景可用 `role="meter"` 的三段式，但不做成主 UI。
- `stance` 仍是单回合的开放程度，不直接等于关系状态；关系状态由多个稳定节点计算，避免一次模型波动就跳档。
- 每次场景结束最多推进一档；同一场景同一节点幂等，重复刷同一幕不涨。

### 3.3 主动关心

- **触发**：熟悉或信任达到「熟络」以上，且当前上下文适合（回归、收束、角色自己的时间线）；不是每回合都触发。
- **形式**：回归开场的一句关心、幕内的一次主动发问、恋爱页的回访卡。内置线优先用**已写好的台词库**（零模型调用）；自定义场景可以走模型，但要有频率上限。主动关心引用 persona 的偏好 / 边界与已发生的记忆，不凭空编造。
- **预算**：每场最多 1 次主动关心；全局每 24 小时最多 1 次站内主动；22:00–08:00 不主动。用户可以在设置里关掉「角色主动关心」。
- **不做**：不写「你不回我就难过」；不用愧疚文案；不因为关闭主动关心而降低关系；不把主动关心做成推送（主站没有服务端推送）。
- **不写分**：主动关心不写 `proficiency` / `loveProficiency` / `practiceDays` / `stars`，也不进 `/api/assess`。它是 NPC 的关系姿态，不是学习者的成绩。

## 4. 半教练反馈

- **可选**：场景结束出现「关系回顾」卡片，用户可跳过；不强制每次复盘。
- **内容**：
  1. 这段关系发生了什么变化（引用自由输入的原话或明确的选择节点）；
  2. 1–2 个「可以更好的说法」——只基于用户自己打出来的话，不替用户编造；
  3. 一条有 `source` 的恋爱知识卡。
- **不评分**：不给星星、不做 acquisition/performance 归因、不自动写能力分。用户想要严格点评，走次要入口「想被点评」进入教练路径。
- **证据边界**：点选项不等于用户真实表达，不能当引文；只有自由输入可以作为「用户原话」。如果用户全程只点选项，关系回顾只描述剧情事实，不评价表达。
- **语气**：具体、温和、不说「你表现不错」这类空话；不做临床诊断。

## 5. 与 Galgame 的桥

完整的双向交接、关系档案、权威矩阵与局外成长见 [spec-love-bridge.md](./spec-love-bridge.md)；人设的 schema 与两个编辑器见 [spec-love-persona.md](./spec-love-persona.md)。本节只列半教练侧的约束。

- **Studio → 恋爱**：导出故事包 `{ summary, characterPackId?, keyChoices, ending }`；恋爱系统把它变成一条自定义场景或一张「关系回顾」卡。不自动写技能分，不把 Galgame 的 flag 直接当关系状态；用户确认后才初始化关系状态。
- **恋爱 → Studio**：把内置角色/场景导出成 Studio 卡与场景包，供用户 remix；不导出 `hidden` / `secret` / 结局谓词。
- **入口**：`/love` 顶部两个主按钮——「先玩一局」（Studio）与「继续关系」（半教练）；Studio 结束后出现「把这段关系带回半教练」。
- **Studio 侧只读**：关系状态在 Studio 只读、默认折叠；Studio 不写关系状态，也不提供刷好感入口。可见成长只在半教练的关系档案里用叙事阶段 + 关系图鉴 + 故事收藏展示（见桥 spec §6）。
- **判据**：如果用户玩完 Galgame 后没有意愿/入口进入半教练，这座桥就不算成立；先看行为，不先加更多场景。

## 6. 数据与隐私

- 关系状态放进 `socialcoach.love-play.story`（`LoveStoryStore`）新增的 `relationships` 映射；schema 升 v2，旧 v1 读取时补空对象。**不新开独立 slot**，避免再欠一次导出/擦除。
- 导出、恢复、擦除沿用现有 `LOVE_PLAY_PREFIX` 前缀与「重置全部数据」路径；用户可以查看/删除单条 signal，也可以「忘掉这段关系」。
- 关系状态不写主教练，不进 `/api/assess`、`/api/pattern`、首页教练回访、能力雷达。
- 不引入账号或服务端存储；跨标签页继续用 revision + 事件总线。

## 7. 验收

- 纯函数 reducer：三个维度只在允许的节点变化；同场景同节点幂等；每场最多一档；上限与时间窗正确。
- 主动关心：达到阈值才触发；每场 1 次、24 小时 1 次、夜间静音；关闭开关后不出现；不写分。
- 关系回顾：只引用自由输入；全程点选项时只描述剧情；跳过不留下副作用。
- 数据：v1→v2 迁移不丢档；导出/恢复/擦除覆盖 relationships；跨标签页冲突不静默覆盖。
- 浏览器：在 Rio 一场与一条自定义场景走通「关系状态 → 主动关心 → 关系回顾」；桌面 Chromium 通过即可，真机另记。
- `pnpm check` / `pnpm build` 全绿。

## 8. 非目标

- 不改主教练的阻力、证据式复盘与能力估计。
- 不做可刷好感、签到、streak、付费加成、排行榜。
- 不做服务端推送、账号、云存档。
- 不做通用聊天陪伴机器人；半教练只服务恋爱故事。
- 不做临床评估、心理诊断、危机干预。
