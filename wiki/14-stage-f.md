# Stage F：恋爱与 Galgame 双系统

E10 交付后，恋爱线已经能像 Galgame 一样读、存、回看、走到结局；但它仍然是「作者写好的剧本 + 教练式统计」的混合体。2026-10-21 用户拍板把恋爱拆成两套系统：

- **恋爱系统（半教练）**：告诉用户怎么更好地恋爱，有关系状态（好感/信任/熟悉），高关系会主动关心；不强制阻力，不强制复盘。
- **Galgame 系统（Love Studio）**：用户生成文本、人物、立绘、场景；先玩一局，再把关系带回半教练。
- **主教练**：文字 / 3D / 自定义排练的阻力与证据式复盘不变。

三套系统有三套内容契约，见 [spec-love-semi-coach.md](./specs/spec-love-semi-coach.md) §2。主教练的「NPC 不讨好」不再拿来否决恋爱/Galgame 需求；平台级约束（授权、安全、导出/擦除、产品名）仍然适用。

## 用户旅程

```
/love
├─ 「先玩一局」 → Love Studio（生成式 Galgame）
│     └─ 玩完 → 故事包 / 角色包 / 关系回顾
│           └─ 「把这段关系带回半教练」 → 剧本模式 + 关系状态
└─ 「继续关系」 → 半教练剧本模式（内置 66 场 + 自定义场景）
```

初始实践在 Studio，成长闭环在半教练；用户也可以跳过 Studio 直接进入半教练。**没有回链，两个系统就是两个产品**，所以桥接是 Stage F 的验收项，不是加分项。

人设是两边的共享资产：Studio 是完整的 Tavern 工作台（卡、世界书、预设、立绘、场景、声音），恋爱系统提供聚焦编辑器（玩家 persona、角色身份、关系约束）和 `.scpersona` 导入导出。两边不要求用户装同一个运行时才能改人设，也不做两套字段名。详见 [spec-love-persona.md](./specs/spec-love-persona.md)。

## 已拍板的边界（2026-10-21）

1. **Tavern 导入分工**：Studio 做完整导入；恋爱系统只吃 `.scpersona` + 基础 JSON，完整 PNG/世界书/预设/立绘包引导到 Studio。离线直吃卡是唯一例外，必须共享 Studio parser（MIT）并加 round-trip 契约测试，不写第二套。
2. **玩家 persona 与教练 profile 分表**：只提供显式「复制到教练档案」并需确认，不自动双向同步。
3. **Studio 不参与关系养成**：关系状态只读、默认折叠；没有提升关系状态的操作、任务或提示。
4. **局外成长用叙事阶段**：陌生 / 认识 / 熟络 / 亲近 + 关系图鉴 + 故事收藏；不做战力、EXP、签到、streak、付费加成。等级即使以后出现，也只能是只读派生，不能兑换奖励或加成。

## 交付顺序

1. **F0**：文档与规则先落（本批）。
2. **F2 P0–P1 + F6 P1**：先把「用户能在 Studio 初始实践」跑通，同时交付恋爱系统的聚焦人设编辑器与 `.scpersona`；这也是用户明确想要的效果。
3. **F1**：半教练关系状态与主动关心；可与 F2 P2 并行。
4. **F5**：桥与局外成长在 F1 + F2 P1 之后接上；没有桥，F2 的故事带不回半教练。
5. **F6 P2**：Studio 完整 Tavern 工作台、世界书/预设/立绘/声音与 AI 生成，随 F2 P2 交付。
6. **F3**：美术升级并行，不依赖 Studio。
7. **F4**：托管 Studio 最后，按 F2 P0–P2 的行为数据决策。

## 停止 / 转向信号

- **Studio 装了但没人玩**：先修安装/入口，不加新生成能力。
- **玩完不回半教练**：先修回链/故事包，不扩内置剧情。
- **主动关心被当成打扰**：先修预算/开关/文案，不降关系或加推送。
- **关系状态变成刷分**：停，回到「只在故事节点变化」；不做签到/streak。
- **Studio 生成的人设带不回 / 不想带**：先修桥的导入预览与恋爱编辑器，不加更多生成能力。
- **两个系统各改一份人设导致冲突**：先修 schema/版本/合并 UI；不要用实时同步掩盖数据模型问题。
- **剧本模式美术升级后玩家仍记不住任何一幕**：停整条美术投入，先验证故事本身。

## 发布门槛

沿用 [13-stage-e.md](./13-stage-e.md) 的发版门槛：同步远端、相关回归、中英/明暗/手机桌面、`pnpm check` / `pnpm build`、最终差异审阅。Studio 是独立运行时，另加：

- 本地安装/启动文档可复现；主站未启动 Studio 时不报错。
- 授权与素材检查：不含 CC BY-NC-SA 立绘；UGC manifest 有 `source` / `license`。
- 密钥：聊天 BYOK 仍浏览器直连；图片 token 不落库、不回显。
- 真机/真人试玩不作为本阶段工程阻塞，但 Studio 的 GPU 语音、本地安装、实际玩家是否愿意回半教练，必须单独记录为「未经玩家验证」。
